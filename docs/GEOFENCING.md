# 家与公司 · 地理围栏

这是供操作者自行构建和部署的功能，不附带任何真实地点、授权或后台服务。
入口：设置 → 位置共享 → 家与公司 · 地理围栏。

## 手机与隐私

- 最多 home/work 两个地点；用户搜索、定位或地图选点，默认半径300米，可调100–1000米。
- 中心坐标和地址只保存在手机，不进围栏配置/事件请求。区域状态只表示最后一次观察，不是实时路线。
- 围栏分享独立、默认关闭，不继承健康或原按需位置分享权限。开关保存用户意愿；系统能力不足显示等待，不强制回弹。
- 系统后台 `CLCircularRegion` 监控要求 Always、精确位置与区域监控能力。后台刷新不可用会提示，不虚构监控成功。
- AppDelegate恢复后台区域回调；前台恢复对账，并在已有使用期间/始终授权下做一次新定位，按距离和精度确认初始状态。不需要先跨界，不持续GPS。
- 自动前台请求60秒内合并、25秒超时。边界/精度不确定保持未知，不把所选地点冒充当前位置。首次/恢复确认不是刚到达。
- 页面显示在家、在公司、范围外、定位中或待确认；超过15分钟的本机观察标为上次确认。
- 当前配置revision隔离旧回调。原子受保护文件保存配置、观察和稳定ID队列；按服务地址/凭据哈希隔离，不存凭据、不进备份。
- 本机队列最多64条、7天；失去ACK重试原ID。关闭停止监控并更新revision。切换服务不将旧队列误发到新服务。
- iOS调度、弱信号、重启首次解锁前、强退和断网都可能影响及时性；不能保证每次后台进出立即上传。

## 后端与模型可见性

沿用owner认证：`/v1/location/geofences/{status,config,event}`。
独立 `geofences.sqlite3`（0600）。配置CAS，事件按revision/device/sequence隔离，重复ID幂等。
仅接收标签、半径、状态、原始观察时间及协议ID，拒绝坐标/地址或未知字段。
最多128条/7天；6小时标stale，上传延迟超过5分钟标delayed，90秒内反向变化标boundaryUncertain。

手机的首次状态也通过同一队列上传，不是只显示在手机。最新观察进入**已有普通聊天和Pulse输入**，
不增加模型唤醒、不合成聊天消息；其他兼容实例需要各自部署、独立设置与授权。
时间/来源/新旧状态明确，不能从离家推断目的地，不能把旧补传说成刚发生。
原按需位置请求与续答授权保持独立，不提供让模型代建真实围栏的工具。
